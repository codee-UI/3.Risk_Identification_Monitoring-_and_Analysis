# Security Monitoring Guide

Companion to the interactive simulator: working principles, pros and cons, applications and a glossary.


## 1. Layers: Strategic, Tactical, Operational

Organizations run IT and OT (operational technology) in three management layers with middleware (integration and communications) in between. IoT devices, user interfaces and IaaS/PaaS/SaaS cloud services sit across these layers, and every layer needs security monitoring.

**Flow:** Goals → Plans → Work → Attack → Logs → Risk report

### Working principle

1. **Set strategy**: Leaders define high-value objectives with time frames of months to years.
2. **Plan tactically**: The middleware layer (integration and communications) turns objectives into granular plans and schedules.
3. **Operate**: Operational tools, IoT/OT devices, UIs and IaaS/PaaS/SaaS services carry out business processes step by step.
4. **Attack arrives**: Most attacks hit the tactical or operational layer, such as a point-of-sale device or a smart building.
5. **Collect security data**: Logs, real-time sensors and human guards report to central correlation systems.
6. **Escalate**: Serious findings are reported upward, because a strategic threat can damage the whole business.

### Pros

- One shared view of risk from boardroom to device
- Surveillance covers IT, OT and IoT together

### Cons

- Heterogeneous systems are hard to integrate
- Legacy OT often cannot run monitoring agents

### Applications

- **Commercial:** Retail point-of-sale, smart buildings, logistics
- **Defense:** Command-and-control (IT) linked with weapon and platform control (OT)
- **Other:** Power grids, hospitals, smart cities, manufacturing

## 2. DLP: Data Loss Prevention

DLP keeps structured and unstructured data under organizational control and in line with policy. It has three components: discovery and classification, monitoring, and enforcement.

**Flow:** Scan → Policy → Data out → Match! → Block/encrypt

### Working principle

1. **Discover and classify**: The engine scans data at rest and tags it (public, internal, confidential). This is ongoing, and most cloud DLP focuses here.
2. **Define policy**: Administrators define usage policies and push them to endpoints, servers and gateways.
3. **Monitor use**: Data in use and in motion is watched on workstations, servers, storage and at the gateway (HTTP/S, SMTP, FTP).
4. **Detect violation**: The gateway inspects content against policy. Encrypted traffic may need SSL interception.
5. **Enforce**: Options are alert and log, block, reroute for confirmation, or encrypt before the data leaves.

### Pros

- Reduces security and regulatory risk (GDPR, HIPAA, PCI DSS)
- Visibility into where sensitive data lives and moves
- Flexible topologies: network, storage, client

### Cons

- Often requires enterprise architecture changes
- Client DLP is costly to roll out on every endpoint
- Gaps appear if hybrid cloud and on-premises policies differ
- Tuning needed to limit false positives

### Applications

- **Commercial:** Banks protecting card data (PCI DSS), healthcare (HIPAA), SaaS tools like Microsoft Purview
- **Defense:** Stopping classified data leaving via email or USB, and guarding cross-domain transfers
- **Other:** Law firms, universities, research labs, cloud access security brokers

## 3. Real-time vs non-real-time monitoring

Real-time monitors (network and host IDS/IPS) act like a burglar alarm. Non-real-time monitors (application logs, system logs, integrity monitoring) are like the footprints left behind. Each fills a different niche.

**Flow:** Event → Live → Alert → Log → Evidence → Tuning

### Working principle

1. **Event occurs**: A user or attacker action generates an event.
2. **Real-time detection**: The IDS sees it immediately, alerts administrators, logs it and (if IPS) may stop it.
3. **Alert analyst**: The analyst receives the alert and responds while the intruder is still present.
4. **Log for later**: The same event is saved in system and application logs and compared with the configuration baseline.
5. **Review afterwards**: Investigators and auditors reconstruct what happened. Log practice follows NIST SP 800-92 and ISO 27001 A.12.4.
6. **Tune**: Tuning customizes defaults so real attacks are true positives and normal traffic is not a false positive.

### Pros

- Real-time stops or limits damage
- Logs give durable evidence and compliance proof
- Together they give wide coverage

### Cons

- Real-time systems create false positives and need tuning
- Non-real-time finds out after the attacker is gone
- Log storage and protection take effort

### Applications

- **Commercial:** Security operations centres using Splunk or Sumo Logic
- **Defense:** IDS on tactical networks and forensic logging on classified systems
- **Other:** Compliance audits (ISO 27001), hospitals, universities

## 4. Events of interest

Incident detection starts by finding events of interest. Signals are either precursors (warnings) or indicators of compromise (attack likely in progress). Analytics must narrow millions of events to a number humans can review.

**Flow:** Millions → ~10,000 → ~200 → IoC

### Working principle

1. **Events flood in**: Large public-facing systems create millions of events daily.
2. **Filter**: Automated triage flags unusual items: unexpected shutdowns, new devices or regions, odd file movement, resource spikes, repeated door retries.
3. **Reduce again**: Further correlation cuts the list to about 200 that analysts can judge in near real time.
4. **Decide**: Most are benign (maintenance, support). An indicator of compromise goes to a managed incident workflow.

### Pros

- Focuses scarce analysts on likely attacks
- Covers IT, OT and physical signals

### Cons

- Benign events can look suspicious
- Alert fatigue if filtering is poor

### Applications

- **Commercial:** E-commerce fraud and order-abuse detection
- **Defense:** Cyber watch floors triaging sensor alerts
- **Other:** Smart buildings, energy utilities, hospitals

## 5. IP flow (NetFlow)

A router or switch fingerprints each forwarded packet using 5 to 7 attributes. NetFlow (Cisco) uses: source IP, destination IP, source port, destination port, layer 3 protocol, class of service and device interface. Packets with the same fingerprint form a flow.

**Flow:** Packet → 7 attrs → Packet → Count → Flows

### Working principle

1. **Packet arrives**: Host A sends a packet toward the destination.
2. **Fingerprint**: The device records the seven attributes. A matching fingerprint joins an existing flow.
3. **Forward**: The packet continues to its destination normally.
4. **Tally**: The cache counts packets and bytes per flow, condensing huge traffic into a small database. That is why it scales.
5. **Export and read**: Analysts read origin, receiver, application (ports), priority (CoS), interface and volume to understand behaviour.

### Pros

- Scalable summary of huge traffic
- Shows who talks to whom, using what, how much
- Reveals baselines and anomalies

### Cons

- No packet content
- Cannot see inside encrypted payloads
- Needs collectors and storage

### Applications

- **Commercial:** ISP capacity planning and DDoS detection, enterprise traffic baselines
- **Defense:** Network situational awareness and spotting data exfiltration
- **Other:** Campus networks, cloud providers, billing

## 6. Full packet capture

Capture devices sit at ingress and egress points and record every packet crossing the border. Traffic is consolidated to few points using VPN tunnels and mandatory routing.

**Flow:** All packets → Forward → Store → Dump → Evidence

### Working principle

1. **Traffic arrives**: All inbound and outbound packets are routed through the capture point.
2. **Pass through**: Traffic continues to its destination in the network.
3. **Store raw data**: Each packet is saved. Storage must cover your detection delay: knowing of a breach three months ago with one month of capture is useless.
4. **Packet dump**: Extract by IP, protocol or time, then analyze with tools or replay web traffic in a simulated browser.
5. **Use the findings**: Evidence of conduct or attacks, and signatures for IDS/IPS, come from this analysis.

### Pros

- Complete raw evidence for incident response
- Source for new IDS/IPS signatures

### Cons

- Very high storage cost
- Not an IDS or IPS itself
- Cannot natively decrypt SSL/HTTPS
- Needs consolidated network design

### Applications

- **Commercial:** Breach forensics at banks and telecoms (e.g. Wireshark, Arkime)
- **Defense:** Forensics and threat-hunting on defense networks
- **Other:** HR conduct investigations, research networks

## 7. Risk monitoring and continuous monitoring

Risk management is a never-ending cycle. Monitoring confirms controls work and supports near real-time detection. Monitoring is not trending: security analytics correlates many log entries to find the few suspicious ones. Monitoring also differs from auditing.

**Flow:** Controls → Changes → Risk levels → Trigger → Update

### Working principle

1. **Controls deployed**: Risk response implements controls and leaves residual risk in the risk register.
2. **Watch for change**: Track asset value, new threats, new vulnerabilities (and patches) and new legislation.
3. **Report**: Results go to management, meet legal reporting duties and support audits.
4. **Trigger reassessment**: Mergers, new processes, new laws, new threats or a schedule (such as every three years) start a new assessment.
5. **Loop**: The new assessment drives new or tuned controls, and the cycle repeats.

### Pros

- Proves compliance (legal, regulatory, contractual)
- Catches new risk early
- Gives management clear evidence

### Cons

- Continuous cost and skilled staff
- Tool noise and patch-testing burden

### Applications

- **Commercial:** Splunk, Sumo Logic, SolarWinds for enterprise visibility
- **Defense:** Continuous monitoring in government risk-management frameworks
- **Other:** Finance, health and cloud compliance programs

## 8. Evaluating control effectiveness

Controls decay: users click through warnings or bypass them, attackers adapt, and software or business logic changes. Security professionals must prove protection is real, not an illusion.

**Flow:** Check → Yes → Test → Measure → Fix

### Working principle

1. **Control installed**: A control is put in place to mitigate a risk.
2. **Is it present?**: Confirm the control exists, such as a written policy.
3. **Is it operating?**: Confirm it works in practice: does the locked screen stop access, and do users comply?
4. **Does it cut risk?**: Confirm the result: is the risk actually reduced?
5. **Decay found**: Alert fatigue, bypasses and system changes erode the control, so it must be repaired, reconfigured or replaced.

### Pros

- Avoids a false sense of security
- Finds failing controls before attackers do

### Cons

- Requires regular testing resources
- User compliance is hard to measure

### Applications

- **Commercial:** SOX, ISO 27001 and PCI audits, red-team testing
- **Defense:** Security control assessments and penetration tests
- **Other:** Hospitals, universities, public services

## Glossary

| Term | Full form | Meaning |
|---|---|---|
| DLP | Data Loss Prevention | Controls keeping data under organizational control |
| GDPR | General Data Protection Regulation | EU privacy law |
| HIPAA | Health Insurance Portability and Accountability Act | US health-data law |
| PCI DSS | Payment Card Industry Data Security Standard | Card-data security standard |
| SSL | Secure Sockets Layer | Older encryption protocol for web traffic |
| HTTP/HTTPS | Hypertext Transfer Protocol (Secure) | Web protocol |
| SMTP | Simple Mail Transfer Protocol | Email sending protocol |
| FTP | File Transfer Protocol | File transfer protocol |
| IDS | Intrusion Detection System | Detects and alerts on attacks |
| IPS | Intrusion Prevention System | Detects and blocks attacks |
| SIEM | Security Information and Event Management | Collects and correlates logs |
| NIST SP 800-92 | Guide to Computer Security Log Management | Log-management guidance |
| ISO 27001 | International standard for information security management | Annex A.12.4 covers logging |
| IT | Information Technology | Business computing systems |
| OT | Operational Technology | Systems controlling physical processes |
| IoT | Internet of Things | Networked physical devices |
| IaaS | Infrastructure as a Service | Rented servers, storage, networks |
| PaaS | Platform as a Service | Rented application platform |
| SaaS | Software as a Service | Rented software |
| UI | User Interface | How people interact with systems |
| NetFlow | Cisco network flow protocol | Summarizes traffic into flows |
| CoS | Class of Service | Traffic priority |
| VPN | Virtual Private Network | Encrypted tunnel |
| TP / FP | True / False Positive | Real attack vs harmless alert |
| IoC | Indicator of Compromise | Signal an attack is likely underway |
| CPU / GPU / RAM | Central / Graphics Processing Unit, Random Access Memory | System resources |
| HVAC | Heating, Ventilation and Air Conditioning | Infrastructure that can signal events |
| SOC | Security Operations Center | Team that monitors security |

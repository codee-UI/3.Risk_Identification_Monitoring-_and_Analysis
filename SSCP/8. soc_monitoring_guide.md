# SOC Monitoring, SIEM & Incident Triage – Study Guide

## Flow
Sources → **Clipping** → **SIEM** (aggregate, normalize, correlate) → **Triage** (event of interest → indicators → non-intentional vs. Indicator of Compromise) → **Response** (passive / active) → **Document & escalate**.

## Technologies
### 1. Log Management
**Steps:** select critical resources → set clipping levels → filter → consolidate to SIEM → retain (legal/PCI; else 3 months online + 1 yr offline) → protect and review (chain of custody for incident logs).
**Pros:** less noise/storage; forensic and compliance evidence. **Cons:** over-clipping hides attacks; clip levels are sensitive; storage cost.
**Used in:** banks/retail (PCI DSS), healthcare (HIPAA), cloud ops, government audits.

### 2. SIEM
**Steps:** aggregate (firewalls, IDS/IPS, hosts, IAM) → normalize → correlate (time, space, entity) → analyze → alert/report → secure storage.
**Pros:** single pane of glass; faster investigations. **Cons:** cost, skills, early false positives, time-skew and VPN masking.
**Used in:** enterprise SOCs/MSSPs (Splunk, QRadar, Sentinel), defense/government SOCs, energy/pipeline OT, SUNBURST (2020) community response.

### 3. IDS / IPS (EDR/XDR)
**Steps:** capture → detect (signature or anomaly) → alert → passive response (log, alert, packet capture) or active response (TCP reset, dynamic ACL, block system call) → maintain/tune.
**Pros:** early warning; automatic containment. **Cons:** maintenance, latency, false positives/self-DoS, attackers adapt faster. Never counter-attack (legal risk).
**Used in:** Snort/Suricata, NGFWs, CrowdStrike/Cortex XDR, CISA EINSTEIN, military, telecoms, hospitals.

### 4. Incident Triage & Escalation
**Steps:** event of interest → separate non-intentional (accident, weather, overload) from hostile → IoC → review response plan → analyze (when, where, malware, entry point, identities, data compromised; Kill Chain/ATT&CK) → document and escalate.
**Pros:** focuses analysts; audit trail. **Cons:** needs balanced risk appetite; slow if escalation unclear.
**Used in:** financial/healthcare SOCs, CERTs, critical infrastructure, military cyber commands.

## 5. Monitoring Controls
Choose: technique (HIDS / NIDS / logging), paradigm (signature vs. statistical anomaly), timeliness (real-time vs. scheduled), reporting (push vs. pull), update policy, tuning, careful automatic response. Deploy by asset value, justified by risk assessment. Maintain: current signatures, tested engine updates, tuning (disable irrelevant OS signatures; don't miss relevant ones), change-control integration.
**Passive response:** log, console alert, packet-flow capture, page/SMS/email. **Active:** TCP reset, dynamic ACL, HIDS blocks system call, access-control lockouts. Never counter-attack.
**EDR/XDR/UEBA/threat hunting:** MITRE-style patterns, longer look-back than HIDS/NIDS, community-trained ML. **Purposes of managing security info:** detection/response first; troubleshooting and forensics second.

## 6. Logging Architecture, SIEM Models, Correlation
- Centralized logging beats searching hundreds of local logs. Distributed collectors (agents; Flume/Chukwa for HDFS; Splunk) scale; hosted services are cheaper but need internet.
- SIEM models: self-hosted/self-managed; cloud SIEM self-managed; hybrid self-hosted; SIEM as a Service.
- Correlation: time (NTS, controlled skew), space (location/pipeline), entity (identity; VPNs complicate).
- Retention: PCI DSS 1 yr (3 months online); otherwise 3 months online + 1 yr offline, then earliest request + 3 months = standard. Protect logs from tampering/disclosure. Anomalies: timestamp gaps, lockouts, writes to protected dirs. Incident logs: save from all devices on the intruder path, chain of custody, Legal sets retention.

## 7. Baselines and Event Data Analysis
Baselines (classification + compliance + controls for CIANA+PS) turn control events into tip-offs. PHI example indicators: reconnaissance, privilege escalation, decrypt attempts, move/copy, session termination.
Analyst questions: when did it start; first visible where/when; malware; initial access node/time; login history; attacker identities; affected identities; other objects accessed; data compromised; attacker aware of detection. Use Kill Chain / ATT&CK and CVE links. Analysts escalate to managers with authority; document for forensics/compliance (e.g. PII breach notification).

## 8. Visualization, Metrics, Trends
Dashboards (trends, status, timelines), system/geography maps, gauges, heat maps, sparklines, fever charts. Answer management's audit questions (compliance, urgent issues, risk posture change, vs. prior audits, ROI of controls). Build: mock up → find data → select/filter → format → ask DB admins to build. Workflow mindset: checklists for initial alarm response.

## 9. Risk Management
- **Treatment:** avoid, accept, mitigate, share/transfer; residual risk. SLE = asset value × exposure factor; ALE = SLE × ARO.
- Risk assessment factors: threats, vulnerabilities, likelihood, impact, asset value (NIST SP 800-30 Rev.1). Senior management sets tolerance. NIST RMF (aligned with ISO/IEC 27005, 31000): frame, assess, assess vulnerabilities, review.
- CVSS (FIRST.org). ATT&CK 14 tactics: Reconnaissance, Resource Development, Initial Access, Execution, Persistence, Privilege Escalation, Defense Evasion, Credential Access, Discovery, Lateral Movement, Collection, Command and Control, Exfiltration, Impact.
- Vulnerability life cycle: analyze/assess → track in risk register → prioritize → treat.
- Risk review: control present / operating / effective; new assessment on merger, re-engineering, new processes, laws, threats, time.
- Legal/regulatory: SOX, HIPAA, GDPR; assessments incl. scanning, ethical pen testing, audits.
